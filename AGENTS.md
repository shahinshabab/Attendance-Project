# Attendance project context

This is the working directory for an office fingerprint attendance system. The user's board is an **ESP32 development board with a USB connector and ESP-WROOM-32 module**, not a bare module. The other parts are an R307 optical UART fingerprint sensor and a Robocraze four-pin 128x64 I2C OLED. A Pico is an alternative idea, not an implemented firmware target.

- ESP32 Arduino/PlatformIO source: `firmware/`. GPIO16 receives sensor TX, GPIO17 transmits to sensor RX, OLED SDA21/SCL22, optional mode button GPIO25 to GND. Check actual board/module markings before wiring changes.
- Server and dashboard: `backend/`, Python FastAPI + SQLite. USB bridge: `tools/device.py`. Windows entrypoints: `scripts/`.
- Use `.venv/Scripts/python.exe` and `scripts/device.ps1` for builds. The wrapper resolves the existing Windows 8.3 path before setting `PLATFORMIO_CORE_DIR` to this project's `.pio-home`; the long OneDrive path hit the Windows compiler command-length limit. Do not move source files to solve this.
- Tests: `.venv/Scripts/python.exe -m pytest -q`. Real HTTP smoke check: `-m tools.smoke_server`. Firmware: `scripts/device.ps1 build`.
- Never print or commit `.env` or `firmware/include/config.h`. They contain locally generated keys/credentials. Do not disable TLS certificate validation for internet connections.
- Preserve attendance records, queued device events, fingerprint templates, and database volumes. Filesystem initialization is a first-install action, not a fix to run automatically on failures. Do not reassign a historical sensor slot to a different employee.

Keep event file names at 31 characters or fewer. No attendance had been saved before this fix.
